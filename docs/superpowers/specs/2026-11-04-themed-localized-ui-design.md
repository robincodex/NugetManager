# 主题、国际化、多选包源与原生交互

## 目标与现状

保持 .NET 10、Native AOT、Aprillz.MewUI 0.22.1 和现有三栏工作流，补齐已安装页加载环，
支持系统/浅色/深色主题、中英文即时切换、原生分段标签、多选包源与包行右键链接。
保持工作区、项目范围、批量勾选、安装升级事务及恢复语义不变。

当前状态栏已有 ProgressRing，但中栏无工作区提示和“正在检测”提示仍为纯文本。
窗口存在硬编码浅色背景、中文文案；包源状态仅支持 null=全部或单个名称；
元数据只有 ProjectUrl，没有单独的仓库 URL。上述内容均需要调整，不能只替换表面控件。

## 用户已确认

- 语言：简体中文、英文；默认跟随系统，可即时切换并记住选择。
- 包源：默认全选；选一个源最多 30 个，多个源每源最多 10 个；空选不查询。
- 采用主界面直接切换主题/语言，不新增独立设置窗口。
- 已确认交互草图 v2：保留三栏；顶部主题/语言入口；原生分段标签；
  包源勾选弹出层；已安装模式禁用包源并保留选择；右键两项链接，缺失禁用。
- 草图仅是布局和交互说明，不是真实热门排行，不是生产中的 Web 界面。

## 方案比较

### A：统一升级原生主界面（用户选择）

复用现有窗口与控制器。顶部直接放置主题和语言选择器，分段标签替换两个按钮，
包源选择器改为多选弹出层。扩展目录和控制器的多源查询，统一主题资源与字符串资源。
优点是入口直接、没有额外导航；代价是本轮需要贯穿状态模型而非零散控件替换。

### B：独立设置窗口

主题和语言集中在设置窗口，其余同 A。主界面更简洁，但操作多一步，增加窗口、
状态同步和测试范围。本轮不采用。

## 界面与主题

- 顶部提供主题选择：跟随系统、浅色、深色；首次默认为跟随系统。
- 使用当前 MewUI 的 ThemeVariant/ThemeManager 能力，不引入新 UI 框架或升级包。
- 系统模式下随 MewUI 系统主题通知更新；显式浅色或深色不被系统变化覆盖。
- 背景、分隔线、选中态、强调色、提示色、正文与次要文字来自主题配色或其语义派生。
  MainWindow、确认/恢复/错误弹窗均检查；不能出现深色主题中的白底白字、不可读警告。
- 主题变化重绘动态包行、详情和图标，不重新打开工作区、不重发包查询、不重置选择。
- Installed/Browse 使用 MewUI SegmentedControl，保持现有切换、搜索焦点和初次浏览加载行为。
- 包源入口与分段标签同排靠右；顶部主题和语言在窄窗口允许合理排布，但不遮挡主要入口。

## 加载状态

- 中栏“正在加载工作区”“正在检测更新”显示独立 ProgressRing 和文字，不仅依赖底部状态栏。
- 搜索、初始浏览、版本、包详情、写入状态保留各自的加载环及已有取消入口。
- “更新检测未完成”是终态警告，不应继续旋转；失败、取消、切换工作区、
  过期响应被忽略及隐藏/移除控件时，相关动画必须停止。
- 数据已存在时更新检查可保留原列表，同时显示检查进度。
- 不能把“是否存在结果”当作加载状态；明确覆盖已安装页首次加载和重载。

## 国际化与偏好

- 界面语言提供跟随系统、简体中文、English。
- 跟随系统按启动时的 UI culture 选择：中文使用简体中文资源，其他语言使用英文资源。
  本轮不增加运行期间 Windows 区域设置变化的独立监听；用户可即时切换选择器。
- 主题和语言保存到本用户 LocalApplicationData 下 NugetManager 的独立偏好文件，
  不写入工作区、不修改 NuGet.Config，也不与恢复记录混用。
- 偏好首次不存在使用系统默认；损坏、读取或保存失败明确提示，不伪装为已保存。
  使用可靠的替换写入，避免半写文件；不保存凭据或私有包内容。
- 使用 AOT 安全的资源方案。键和格式参数集中管理，中英文资源键集合一致，
  不靠批量字符串替换或只翻译控件标题。
- 应用自有窗口、菜单、提示、确认、恢复说明、状态、分组和错误前缀均提供中英文。
  包名、路径、源名、作者、描述、许可证和 SDK/操作系统原始诊断不翻译。
- 当前状态应保留稳定消息身份和参数，显示时解析资源，避免已生成的中文状态在切换后残留。
  不为本轮国际化改写事务行为或吞掉底层错误细节。
- 切换语言不清空工作区、搜索框、勾选、选择源、选中包、分页和详情；不用重启。
  模态确认存在时沿用原生模态阻止父窗口操作；新打开弹窗使用当前语言。

## 多选包源

- 源列表仍来自当前工作区启用的 NuGet 配置。弹出层提供全选及各源复选框，
  支持部分选中的全选状态；入口显示全部源、单个源名称、已选 N 个源或未选包源。
- 默认选中所有启用源。空集合明确代表不查询，不能重新解释为全部源。
- 状态区分“全部源”意图和显式子集：配置刷新时全部源纳入新启用源，
  显式子集仅保留仍启用的项；子集全部失效则保持空选并提示重新选择。
- 工作区重新打开恢复默认全选；本轮不跨工作区保存包源勾选。
- 仅影响浏览；已安装依赖和更新候选不按源过滤。已安装模式禁用入口但保留勾选。
- 一个源的空关键词浏览最多 30 项；两个或更多源，每个最多 10 项；
  数量按实际启用且选中的源数计算。继续区分热门和普通浏览。
- 关键词查询只针对选中源；保留现有每源 20 项分页，源身份保留，不跨源合并同 ID。
  按源展示结果/诊断，分页追加不得重复或混入旧源。
- 保持 NuGet SDK 负责常规搜索、配置和认证，不自行转发私有凭据。
  热门仅复用已验证的官方 nuget.org 能力；不扩展未经验证的排序接口。
- 缓存键使用工作区、无序规范化源集合和预发布选项；勾选顺序不同视为相同选择。
  刷新失效缓存，失败不能永久缓存为成功。
- 源切换同时提交当前搜索框文本，取消/忽略旧查询、分页、详情和版本请求。
  取消的防抖不能导致当前文本被旧查询覆盖；同包的详情来源仍绑定具体结果所在源。
- 写入等冲突操作期间禁用源修改；查询中仍可改选，由代次检查隔离旧响应。
- 部分源失败保留其他源结果和分组，诊断提供重试；重试范围清楚标注。

## 包行右键菜单与链接

- 已安装、可升级、隐式依赖和浏览包行均支持 MewUI ContextMenu。
- 固定两项：打开 NuGet 页面、打开 GitHub 仓库；无可用链接时显示但禁用。
- 右键目标使用该包 ID、版本和具体结果来源，不误用右侧另一包的详情；
  不改变批量升级勾选。可以加载/复用该身份的元数据，异步完成后更新菜单状态。
- 官方 nuget.org 包来源可构造其公开包/版本页面；其他源仅在确有已验证详情链接时启用，
  不把私有/本地包 ID 擅自拼到 nuget.org 后当成真实链接，不额外探测公共站点。
  已安装条目无已知官方来源时，通过正常来源元数据解析确认，否则禁用。
- GitHub 仓库优先读取 nuspec repository 的真实 URL；repository 未提供时，
  可用明确指向 github.com 仓库的 ProjectUrl。非 GitHub 的项目主页不能当成 GitHub 仓库。
- 识别标准 HTTPS GitHub 仓库链接及常见 git HTTPS/.git 写法，规范化为可浏览的仓库根链接；
  仅主机精确为 github.com 且有合法 owner/repository 时启用。
  不把 github.com.evil.example、带凭据 URL、文件/脚本协议视为有效链接。
  SSH/scp 等未支持形式不猜测，保留禁用状态。
- 只允许经校验的绝对 HTTP(S) 链接经系统浏览器打开，不用命令行拼接。
  打开失败按现有 UI 错误边界明确通知。
- 缺失链接是正常禁用状态；元数据加载失败保留明确诊断，不能伪装成成功解析但无链接。

## 非目标与实现者可决定的事项

- 不新增源管理、凭据编辑、私有源网页模板、GitHub API 查询、自动翻译包描述或新安装来源策略。
- 不更改确认、写入、回滚、恢复或中央版本管理规则，不自动推送或合并。
- 实现者决定偏好 DTO、资源键命名、MewUI 弹出层具体组合及必要的小型共享投影。
  必须先验证安装版本的 API 和生命周期，尽量复用已有工具及测试，不引入多余依赖。
- 已有会话 worktree 继续使用，不请求另建 worktree。

## 验证与完成标准

- 测试先覆盖中栏加载状态、成功/失败/取消/切换时动画生命周期、主题配色刷新和语言切换状态保留。
- 双语言键集合和格式参数检查；中文/英文的状态、弹窗、菜单与多选源数量文案都有断言。
- 偏好文件首用、加载、保存、损坏、写入失败及原子替换均有隔离测试。
- 真实 SDK 双源测试验证单源 30、多源每源 10、空选不请求、选中子集搜索与分页、
  同包异源、源增删/禁用刷新，以及无序集合缓存身份。
- 元数据测试覆盖 repository、ProjectUrl 回退、无仓库、未知来源、异源同 ID，
  非 GitHub/伪造主机/非法协议，以及浏览器启动失败可见。
- 右键未选中行的链接不能来自当前详情；异步菜单关闭/切包后旧回复不污染新菜单。
- 全量现有测试通过，win-x64 Native AOT 发布无新增裁剪或 AOT 告警。
- 启动最终原生产物，检查系统/浅色/深色、中文/英文、分段标签、
  已安装首次加载/检测加载环、多选/空选、右键两项启用/禁用与链接启动。
- 原生手工验证如果受环境焦点限制，应列出具体未验证场景，不能只用构建成功替代。
- 更新 README；完成后整分支审查，再由用户决定是否合并。
