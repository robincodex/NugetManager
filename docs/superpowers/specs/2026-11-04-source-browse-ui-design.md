# 包源浏览与 MewUI 状态控件改进

## 目标

在现有三栏桌面界面中统一加载状态和操作图标，加入包源选择，并让空关键词浏览直接呈现各源的热门或普通浏览包。保留现有事务、恢复、项目范围和已安装依赖读取行为。

## 已确认行为

- 工作区加载、更新检查、搜索、包详情等等待状态使用 MewUI `ProgressRing`，保留状态说明和已有取消入口。
- 操作性箭头、展开指示等使用 MewUI 支持的图标控件或图标资源；不修改包名、版本或诊断中的真实文本。
- 在“已安装 / 浏览”同一行右侧放置包源下拉框。
- 默认选择“全部源”，源列表来自当前工作区配置中的启用源；不新增或改写源配置。
- 源选择只影响浏览；已安装列表保持完整，在已安装模式禁用源选择并保留选择值。
- 首次进入浏览且关键词为空时自动加载：全部源每源最多 10 个，单源最多 30 个。不足数量时只展示实际结果。
- 全部源按源分组，同名包跨源保留，避免来源信息被去重丢失。
- 支持热门能力的源使用下载量热门；其他源明确显示“普通浏览”，不能把任意第一页称为热门。
- 一个源失败不抹除其他源的结果；对应分组显示诊断和可重试入口。
- 切换源、预发布选项或关键词时清除过期分页结果，取消或忽略旧请求，确保旧响应不覆盖新选择。

## 方案比较

### A：统一 SDK 空关键词浏览

沿用 SDK 搜索和认证，每源读取第一页；实现简单，但 NuGet V3 标准不保证下载量排序。无法满足严格的热门语义。

### B：热门能力适配 + SDK 普通浏览（用户选择）

在确认支持下载量排序的源上使用对应查询能力；不支持、需要认证或本地源通过 SDK 普通浏览，并明确区分标签。默认全部源各取 10 个，单源取 30 个。

NuGet 标准 SearchQueryService 未定义通用热门排序参数，因此实现前需验证源的实际能力和返回顺序。不能凭服务器忽略了未知参数就宣称支持排序；不能仅将任意小样本按下载量排序后称为全源热门。

## 实现边界

- 复用 `NuGetConfigReader`、SDK 指定源参数、现有 catalog/controller 状态与异步响应代次机制。
- 使用带来源的浏览分组及结果身份；详情/版本查询保留选中结果的来源，防止跨源混淆。
- 浏览源不是安装认证或还原源配置的重写入口。安装仍遵守现有 `NuGet.Config`、源映射与安全写入机制。
- HTTP 查询仅用于经过验证且无需额外凭据的热门能力；不自行转发私有源凭据，也不静默绕过 SDK 认证。
- JSON 使用源生成类型；保持 win-x64 Native AOT 可发布。
- 使用已安装 MewUI 版本的实际 API，先确认 `ProgressRing` 与图标 API，不依赖猜测或 Unicode 字形模拟控件。
- 设计者建议缓存当前工作区中按源和预发布条件区分的初始浏览结果，返回浏览页无需重复请求；显式刷新重取。缓存不得跨工作区错误复用。

## 非目标

不按来源过滤已安装依赖，不做源管理或凭据管理，不改变事务升级策略，不强制所有源支持热门。

## 验证

- 控制器/catalog 测试覆盖默认全部源每源 10、单源 30、分组同名包、源切换、旧响应隔离、部分源失败、热门与普通浏览标签。
- 真实 SDK 本地源测试验证空关键词及指定源行为；热门适配用受控 HTTP 数据验证请求、排序语义和失败报告。
- 测试已有已安装列表和操作行为不受源下拉框影响。
- 在真实 MewUI 窗口验证各加载状态、图标、源选择和空关键词浏览。
- 全部测试通过，Native AOT 发布无新增裁剪告警，并启动发布产物验证关键浏览流程。

## 界面

用户已确认浏览器草图：维持原有浅色三栏布局；标签同行右侧放置源选择；中栏按源显示热门或普通浏览分组；详情区和状态栏使用加载环配合说明。
