# NuGet Manager 第一版设计

日期：2026-11-04

状态：已完成设计者自审，待用户批准；不是实现计划

## 1. 意图

为开发者提供独立的 Windows 桌面 NuGet 管理器，使用 .NET 10、
Native AOT 和 Aprillz.MewUI。日常流程是打开工作目录，查看可升级
直接依赖，全选后取消不想升级的包，再批量升级；无需打开 Rider。
以 Rider 包管理的操作效率为目标，不要求第一版覆盖 Rider 所有能力。

仓库目前只有空入口；项目已引用 Aprillz.MewUI 0.22.1，
启用了 PublishAot，并保留现有裁剪描述文件。沿用技术栈，
不把浏览器草图作为产品实现。

## 2. 已确认的目标与边界

- 第一版仅 Windows；以后可能支持 Linux 等平台。
- 使用者必须安装 .NET SDK。
- 打开工作目录，以解决方案或目录内项目为操作范围。
- 支持解决方案汇总视角与单项目视角。
- 自动检测更新；支持全选、取消单项及批量升级。
- 默认允许跨大版本；“包含预发布版本”默认关闭。
- 搜索包，查看基础信息、支持框架和按框架分组的依赖。
- 显示直接引用版本、隐式依赖解析版本及未安装状态。
- 支持按项目安装和卸载。
- 支持 Directory.Packages.props 集中版本管理。
- 单项目升级共享集中版本时，允许影响其他项目。
- 批量操作采用整批成功或整批撤回的规则。

非目标：源配置管理界面、IDE 插件、完整依赖图、漏洞审计、
旧式 packages.config 项目支持及保证升级后业务代码无需修改。
本轮不新增 NuGet 源、不修改认证配置、不做自动集中版本清理。

不能接受的结果：把传递依赖当直接引用升级；隐藏源查询失败；
误修改不相关项目；覆盖用户原有改动；把还原成功说成编译成功；
以空列表冒充检测完成；AOT 发布后关键功能失效。

## 3. Approaches

### A. AOT 主程序 + SDK 命令 + 包元数据读取（用户选择）

MewUI 主程序负责 UI、状态、操作预览和事务编排。
调用已安装 SDK，使用 JSON/结构化输出获取项目及包信息，
执行搜索、更新检测、安装、卸载和还原。
包详情使用本地包清单、缓存与 NuGet 元数据补充。

优点：不在 AOT 进程中嵌入 MSBuild；组件少；
SDK 负责正常 PackageReference 和集中版本写入语义。
代价：必须探测命令能力，处理进程错误、项目求值、
源配置、认证及元数据读取能力差异。

### B. AOT 界面 + 独立托管后台工具（未选择）

后台使用 MSBuild/NuGet 库，集中处理解析、认证和包元数据。
复杂扩展更集中，但增加部署组件和通信协议，
且只有界面程序是 AOT。第一版无需承担这个成本。

## 4. 项目发现与范围

工作目录由用户选择，不默认管理程序自身目录。
工作目录根层存在 .sln/.slnx 时，以选定解决方案内的 C# 项目为主；
没有解决方案时，递归发现 .csproj，排除 bin、obj、.git，
不沿目录链接递归，不重复加载同一规范化路径。

多解决方案时让用户选择，不任意合并；这是设计者的建议。
解决方案内指向目录外的项目仍属该解决方案，显示实际位置。
无法加载的项目保留错误状态，不从总数中悄悄消失。
不支持的项目类型提示原因，不作为可写项目。

解决方案视角按不区分大小写的包 ID 汇总，保留每个项目、
目标框架、声明版本与解析版本，不能把不同版本压成单个版本。
单项目视角只展示该项目依赖；右侧项目列表也只显示该项目，
包括搜索结果页。切换范围清空升级勾选，避免误用旧范围。

集中版本影响范围单独出现在操作确认中，不扩大单项目右侧列表。
评估已加载项目对共享文件的引用；文件也可能被未加载项目使用时，
明确提示无法穷尽这些影响，不宣称只影响当前列表。

## 5. 主界面

采用用户选择的 A 三栏布局：

- 左：工作目录、解决方案选择和项目范围。
- 中：已安装管理页或搜索包页。
- 右：选中包的详情、版本选择、当前范围项目及安装/卸载操作。

已安装管理页按以下顺序排列：

1. **可升级**：直接引用的更新候选；无候选时隐藏整个分组。
   Header 右侧放全选与批量升级按钮；无勾选时禁用升级。
2. **已安装**：项目显式声明的 PackageReference 直接依赖。
   集中管理时版本可来自 Directory.Packages.props，
   不因为版本未写在 .csproj 中而遗漏直接引用。
3. **隐式依赖**：经还原解析的传递依赖，显示解析版本与引入关系。
   不直接参与批量升级。

可升级是快捷操作分组，已安装仍保留全部直接引用；
一个可升级包可以同时出现在可升级和已安装分组。
同一个包在不同项目中直接/隐式角色不同，可以出现在两类分组，
但各自关联的项目不能混淆。

MSBuild 导入文件中的显式引用不是传递依赖。
求值发现此类引用时标注来源；能够定位声明来源则按直接引用展示，
不能安全定位写入目标时保持只读并说明原因，不能错误新增重复引用。
SDK 自动隐式引用另标“SDK 自动引用”，不可卸载或直接升级，
不混入用户显式声明的已安装列表。

搜索采用 SDK 支持的分页查询。输入防抖，可取消过期请求，
只允许最新范围与查询结果更新界面。
没有结果、查询失败、部分源失败和加载中使用不同状态。

包详情展示包 ID、作者、简介、版本、许可证/项目链接（存在时）、
支持框架和按框架分组的依赖及版本范围。
以选中版本为元数据范围，切换版本重新加载详情。
缺失信息显示“未提供”或明确的读取错误，不虚构兼容框架。
框架信息依据包资产和依赖分组，不仅根据包目标名称猜测。

右侧每个项目按实际状态提供：

- 直接引用：显示声明/解析版本，提供“卸载”。
- 仅隐式依赖：显示解析版本，提供“安装”以新增直接引用。
- 未安装：提供“安装”。

多目标框架状态按框架展开，不用一个版本覆盖所有框架。
卸载只移除选定项目的显式引用；包仍可能作为隐式依赖存在。
卸载不删除共享 PackageVersion 条目，避免影响其他项目。

草图采用浅灰/白底、深灰文字、蓝色操作、琥珀色风险提示，
Windows 常用字体、小圆角和细分隔线。真实 UI 使用 MewUI 控件，
首版不引入 WebView，不以 HTML 冒充桌面实现。

## 6. SDK 与数据策略

主程序不加载 Microsoft.Build 求值引擎，不引入托管后台。
使用进程参数列表启动 dotnet，不拼接 shell 命令；
记录命令类型、范围、退出码和脱敏后的错误。
同时读取 stdout/stderr，支持取消、超时及 UI 线程安全调度。
写操作按工作区串行；只读操作有限并发并可缓存。

设计者建议第一版要求具有 .NET 10 命令能力的有效 SDK，
不承诺适配所有旧版 SDK。尊重工作区 global.json；
如果实际 SDK 缺少必要命令，明确阻止相关操作并提示需求，
不静默忽略 global.json 或切换到不兼容 SDK。
程序的目标框架为 .NET 10 不限制被管理项目必须也是 .NET 10。
SDK 安装检测与版本/能力探测在加载阶段执行。

依赖读取采用 SDK 的 package list JSON，并分别保留直接与传递数据；
更新检测采用 outdated 输出，预发布选项映射至 SDK 参数；
显式固定 JSON 输出版本，并验证结果形状，不解析本地化控制台表格。
还原与 MSBuild 结构化求值补充框架、声明来源、集中版本文件位置。
依赖未还原时先运行还原；失败则呈现未完成状态，禁止基于旧数据写入。
加载阶段的还原也可能更新锁文件；不得借“只读加载”静默改写
已有锁文件或项目声明。先检查现有还原状态，需要改变这些文件时
走同样的操作确认与备份流程；派生资产写入明确显示在还原状态中。

升级候选是符合预发布开关的更新版本，不做降级或自动主版本限制。
同包不同项目保留各自当前版本；默认建议最新稳定版，
实际 SDK 返回的候选与目标框架适用性需在预览中显示。
不保证所有最新版本均兼容全部项目；操作后还原是必须的验收。
受条件、VersionOverride、属性表达式或多层导入影响的引用，
必须定位有效声明/写入目标；无法安全处理则列出具体阻塞项，
不能通过新增无条件引用“绕过”原配置。

查询和 SDK 操作使用工作区现有 NuGet.Config 层级及源映射，
不默认覆盖为 nuget.org。源管理延后不代表忽略现有源。
详情优先读 SDK 缓存/本地 .nupkg 清单，再读取可访问 V3 元数据。
首版支持公共 V3 源及现有本地目录源；SDK 可处理的私有源操作继续
交给 SDK，但尚无可用缓存且详情认证不支持时明确显示详情不可用。
不实现新的交互式凭据管理；需要认证的操作提示在 SDK 环境完成认证。
源认证失败、禁用源及无法支持的源协议不得伪装成不存在该包。

JSON 使用 AOT 兼容的 System.Text.Json 源生成；
XML/包清单读取关闭外部实体解析。NuGet 库仅在确有需要且通过
AOT 验证后引入，不为图省事引用整套 NuGet.Commands。

## 7. 安装、卸载与批量升级事务

用户已批准整批成功或整批撤回。安装和卸载采用同样的安全机制。

1. 重新确认范围、包、目标版本、声明来源和预计写入文件。
   预览列出版本变化、跨大版本提示、共享集中版本影响和阻塞项。
2. 用户确认后，备份预计会修改的 .csproj、实际集中版本文件、
   相关已有 packages.lock.json；记录文件是否原本存在和原始字节。
   备份保存在应用操作恢复目录，不提交到用户项目。
   对目录外共享文件同样显式展示实际路径并取得确认。
3. 锁定本应用工作区写操作，检测文件变化，调用 SDK 实施修改。
   集中版本的同一条有效声明只能更新一次，不按项目重复改写。
   不主动改变条件引用、框架条件或集中版本覆盖策略。
4. 对实际受影响的已加载项目执行还原；集中版本影响不止所选项目时，
   验证范围也随之扩大。所有步骤成功后重新读取依赖并重新检测更新。
   仅宣称依赖还原成功，不自动构建所有项目。
5. 任何命令失败、还原失败或用户取消，停止后续修改，
   撤回程序本批拥有的文件修改，再尝试按原配置还原受影响项目。
   显示原始失败、撤回结果及重新还原结果。

备份包含用户操作前未提交的修改，不能用 git reset/checkout 回滚。
回滚只针对预先确认的文件，不删包缓存、不递归清理目录。
新建文件仅在确认为本批创建且无后续外部修改时撤除。
obj 下派生资产不进行目录快照；回滚后通过还原重新生成。

检测到外部并发编辑时不自动覆盖未知修改，停止操作并提供
备份位置和逐文件恢复状态。这是整批撤回的安全例外：
明确标为“回滚受阻/需要恢复”，不能报告整批已撤回。
实现者必须建立可验证的文件所有权/冲突检测，
不能仅凭操作结束后的单次哈希断言所有内容来自本程序。
无法建立安全写入条件的引用应在预检阻止写入。

保留最小操作日志、备份清单及完成标志。程序异常退出后，
下次启动发现未完成操作时提示恢复，不自动覆盖用户文件。
成功完成并刷新后按保留策略清理本应用的备份；
失败或冲突备份在用户恢复前保留。

## 8. 错误与交互状态

加载/还原/查询/预检/执行/验证/回滚各有明确状态及取消入口。
写操作期间禁用重复安装、卸载、升级及范围切换。
只读查询取消不显示假成功；操作失败保留可复制的脱敏诊断。
部分源失败不能将未知候选排除后宣称“全部最新”，
用户必须明确看到检测不完整。
外部链接通过系统浏览器打开，并校验允许的 URI 协议。
不将认证信息写入普通日志或备份无关 NuGet.Config。

## 9. 验收

- Windows Release Native AOT 可执行文件实际启动 MewUI 界面；
  不靠 Debug/JIT 运行作为 AOT 验证替代。
- .sln、.slnx、无解决方案目录发现正确，重复路径不重复加载。
- 单项目筛选同时约束中间列表和右侧项目列表。
- 直接引用/传递依赖/SDK 自动引用正确区分，多框架版本不丢失。
- 无可升级候选时隐藏分组，查询失败时呈现错误而非假空列表。
- 全选后取消单项，只升级仍被选中的直接引用；默认排除预发布。
- 同包不同版本按项目保留并正确升级，不意外降级已更新项目。
- 普通引用及集中版本安装、卸载、升级都由真实测试项目验证。
- 单项目共享版本升级预览并验证其他受影响项目。
- 安装隐式依赖新增直接引用；卸载后重新显示可能剩余的传递状态。
- 搜索选定版本可显示元数据、框架及依赖组；本地源和读取失败明确。
- 整批中途失败、还原失败、取消均测试撤回；操作前用户改动不丢失。
- 外部并发编辑和异常退出恢复不覆盖用户内容，不报告假成功。
- 路径含空格、无 SDK、global.json 约束、网络失败均有明确诊断。

测试使用隔离的临时 SDK-style 项目和可控本地测试源，不修改用户
真实项目做失败实验。UI 草图只用于需求反馈，不能作为上述功能验收。

## 10. 留给实现者的决定

具体 MewUI 控件组合、状态绑定、类/项目拆分、合理的超时与并发上限、
缓存过期、备份保留策略及测试框架，可沿仓库与 SDK 习惯选择。
这些决定不得改变已确认的 UI 范围、依赖分类、升级规则和回滚语义。
Windows 首先验证当前常见桌面架构；发布架构列表在实现计划中明确，
不提前承诺已经验证其他平台。
